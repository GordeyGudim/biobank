# Biobank — информационный банк биологических данных, Вьетнам

## О проекте

Полевые данные ихтиологических экспедиций в дельту Меконга (Вьетнам, 2025–2026):
пойманные особи (сомы *Pangasius*, *Plotosus canius* и др.), их промеры, взятые образцы
(ДНК, гистология, мазки крови, кишечник), траления и параметры воды.

Исходник — Excel-книга `data/source.xlsx`. Задача проекта — **новая реляционная база
данных по схеме `db/schema.sql` (версия 2) и набор инструментов на Python** для импорта,
проверки, правки, выгрузки и отчётов.

Над проектом работают двое: пользователь (ведёт этот репозиторий) и его коллега, автор
документа логического проектирования `docs/Этап2_логическое_проектирование_коллега.docx`.
Схема v2 — согласованный результат обсуждения: наши решения + предложения коллеги.
Визуальная схема — доска Miro «Вьетнам: структура базы данных уловов», раздел 5.

## Пользователь и стиль работы

- Пользователь — **начинающий программист**, работает на **Arch Linux**. Общение — **по-русски**.
- Код и SQL показывать и обсуждать, но новые понятия (JOIN, внешний ключ, транзакция,
  регулярное выражение, фикстура pytest и т.п.) коротко пояснять при первом появлении.
- Объяснять не только «что сделать», но и «почему так» — пользователь хочет научиться.
- Работать по этапам (см. ниже), после каждого этапа — короткий итог и что проверить руками.
- Перед изменением схемы БД — спросить пользователя. Схема согласована с коллегой.

### Команды CLI

| Команда | Что делает |
|---|---|
| `python -m biobank init` | создать пустую `output/biobank.db` из `db/schema.sql` (с подтверждением, если файл есть) |
| `python -m biobank import data/source.xlsx` | пересоздать БД и импортировать книгу; в конце — сводка (сколько чего загружено) |
| `python -m biobank check` | запустить проверки, обновить `data_issue`, вывести сводку по категориям |
| `python -m biobank export [--format xlsx\|csv]` | выгрузить все таблицы + сводные представления (по листу на таблицу; первый лист — data_issue) |
| `python -m biobank report <имя>` | отчёты: `species` (особи по видам и экспедициям), `samples` (образцы по типам/органам/лабораториям), `water` (параметры воды по тралениям), `sites` (места и их посещения), `issues` |
| `python -m biobank link-trawl <label> <trawl_no>` | привязать особь к тралению её же выезда |
| `python -m biobank identify <label> <species> --method ДНК --confidence точно` | добавить запись в историю определений и обновить текущий вид особи |
| `python -m biobank resolve-issue <id> "<как решили>"` | отметить проблему решённой |
| `python -m biobank sql "<SELECT ...>"` | выполнить запрос только на чтение и красиво напечатать результат |

Правки (`link-trawl`, `identify`, `resolve-issue`) — только через проверенные функции в
`edit.py`, в транзакции, с понятным сообщением об ошибке. Перед любой массовой правкой —
резервная копия файла БД (`output/backups/biobank_YYYYMMDD_HHMMSS.db`).

## Схема БД v2 (кратко; подробности и комментарии — в `db/schema.sql`)

```
region (провинция) 1→N city 1→N sampling_site (МЕСТО: где; не меняется между экспедициями)
expedition 1→N sampling_event (ВЫЕЗД: когда; ссылается на место, способ получения, сеть)
sampling_site 1→N sampling_event
capture_method (траление/рыбак/рынок/аквахозяйство) 1→N sampling_event
gear (сеть) 0..1→N sampling_event
sampling_event 1→N trawling 1→N water_measurement (старт/финиш: координаты, вода)
sampling_event 1→N specimen (ОСОБЬ: TL, SL, m, m без порки)
trawling 0..1→N specimen        (если известно; составной FK гарантирует тот же выезд)
species 0..1→N specimen         (текущий принятый вид)
specimen 1→N species_identification N←0..1 species   (история определений)
specimen 1→N sample (ОБРАЗЕЦ: пробирка/стекло/целая особь)
sample N↔M lab через sample_shipment (куда отправлен)
sample 1→N analysis (РЕЗУЛЬТАТ исследования; пока данных нет)
sampling_event / trawling 1→N catch_record (прилов, общая масса)
data_issue — журнал спорных значений
```

Ключевые решения (не менять без пользователя):
- **Место (`sampling_site`) отделено от выезда (`sampling_event`)**: экспедиции будут
  возвращаться на те же точки. Дата хранится в выезде, не у особи.
- **Особь ссылается на выезд всегда, на траление — только если известно.** Составной внешний
  ключ `(trawling_id, event_id) → trawling(trawling_id, event_id)` не даёт привязать особь
  к тралению чужого выезда.
- **Параметры воды привязаны к тралению** (старт/финиш), а не к месту.
- **Промеры (TL, SL, m, m без порки) — колонки `specimen`**, каждую рыбу мерят один раз.
- **Образец (материал) ≠ анализ (результат).**
- Термины: **особь** = specimen (рыба с номером «26 ph»); **образец** = sample (взятый у неё материал).
- В каждом подключении SQLite выполнять `PRAGMA foreign_keys = ON` (по умолчанию выключено!).

### Нумерация проб

- *Pangasius* и родственные — **сквозная серия 1…277**, суффикс = вид: `е`/`e` elongatus, `sp`,
  `ph` hypophthalmus, `mc` macronema; без суффикса — числа, часто как float (`107.0`).
- *Plotosus canius* — серия `1 pc … 178 pc` (варианты: `2pc`, `3 p.c.`, `155  pc`, кириллическое `рс`).
- *Bagarius* `1–5 Bg.`, *Macrobrachium* `1–5 mr`. Особь без номера: `ХХ` (Точка 1, вид «?»).
- Нормализованная метка: `"<число> <суффикс>"` → `specimen.label`; исходная → `label_raw`.

## Правила импорта (маппинг Excel → схема v2)

- **region**: Донг-хап, Виньлонг, Кантхо. **city**: из строки 1 листа (Хонг-нгу, Као-Лань, Кай-Бе,
  Го-Конг, Фу-Донг, Бенче, Ку Лао Дат, Виньлонг, Чавинь, Хоа-Минь, Кантхо, Дан-ан, Thot Not,
  Ан-Лак-Тхон, Шокчанг, Тран-де …). Одинаковые города в разной транслитерации («Хонг-нга»,
  «Хонг-на», Hong-Ngu) объединять, исходный текст сохранять в `sampling_event.notes`.
- **expedition**: по листу-разделителю; даты = min/max дат выездов.
- **sampling_site**:
  - траление → место «Участок у <город>» (без слов «Меконг»/«реки»), координаты = старт первого
    траления первого выезда на это место (реальный замер, решение пользователя); если старт — выброс
    (> 30 км от остальных) или без координат — финиш того же траления, затем следующее траление;
  - рынок → «Рынок <город>»; аквахозяйство → по координатам с листа;
  - рыбак → по координатам (на листах «Рыбак…», в строках «1 рыбак (118)», «2 рыбак (138-142)»,
    «Координаты 1 (155-162)», «точка лова рыбака»);
  - **дедупликация**: участки реки с одинаковым названием (у одного города) — одно место
    независимо от расстояния (решение пользователя); координаты — от первого выезда,
    точные точки каждого траления — в water_measurement; остальные места одного типа ближе ~200 м — одно место (точка 9.5187059, 106.2082146
    встречается на трёх выездах 20, 21, 22.08.2026 — должна стать ОДНИМ местом);
  - лист «Рыбак (самостоятельно 22.08)» содержит две точки: место выезда = «Координаты 1 (155-162)»,
    у особей 163–178 pc — `capture_site_id` = место «Координаты 2 (163-178)».
- **capture_method**: траление / рыбак / рынок / аквахозяйство — по имени листа.
- **gear**: из комментария к шапке «№ траления»; 2 записи; ссылка только у выездов-тралений.
- **sampling_event**: одна строка на лист; `source_sheet` = имя листа; дата рынков NULL → data_issue
  (`event_date NOT NULL` в схеме — для рынков взять дату ближайшего предыдущего выезда и записать
  это в notes и data_issue — решение пользователя).
- **trawling**: по номеру из «старт N»/«финиш N»; время старта/финиша, длительность, скорость,
  промежуточная глубина; комментарии об улове → `catch_note`, о береге/заводах → `notes`.
- **water_measurement**: по строке на «старт» и «финиш» (`point_type`), `coord_source` из шапки
  (Garmin / Google Maps). Строка «точка лова рыбака» (Точка 6.) → `trawling_id = NULL`, `point_type = 'точка'`.
- **species**: справочник в одном написании: Pangasius sp., P. elongatus, P. macronema,
  P. conchophilus, Pangasianodon hypophthalmus (в таблице опечатка «Pangasiodon»),
  Plotosus canius, Bagarius sp., Macrobrachium rosenbergii (в таблице «macrobrahius rozenbergii»).
  Семейства: Pangasiidae, Plotosidae, Sisoridae, Palaemonidae.
- **species_identification**: на каждую особь минимум одна запись: `method = 'морфология'`,
  `identified_on` = дата выезда, `raw_text` = исходный текст вида, `confidence`:
  «пред./предп.» → `предп.`; «Pangasius sp» → `до рода`; «?»/«вид неизвестен» → `не определён`
  (species_id NULL); иначе `точно`. Комментарии «возможно pangasius macronema», «предп. kremfi» → `notes`.
  `specimen.species_id` = текущий вид.
- **specimen**: промеры через парсер чисел; «целая рыба»/«заспиртовали целиком» в колонках → промеры NULL
  + образец `целая особь`. `capture_method_id`/`capture_site_id` заполнять **только если отличаются
  от выезда** (118 pc, 138–142 pc, 64–69 pc — от рыбаков внутри выезда-траления).
  `is_dead` — из «особь мертвая», «особи мертвые», комментариев «мертвый», «из погибшей особи».
  `trawling_id` — NULL (неизвестно). Не угадывать.
- **sample**: ДНК (колонка DNA), кишечник (2026), мазок крови (`preservative` = «этанол 96% (фиксация)»),
  гистология — **по строке на орган**: «26 ph a - печень, 26 ph б - почки» → две строки
  (печень `26 ph a`, почки `26 ph б`); органы: печень, почки, икра, кишечник; у креветок `mr`:
  мышцы, жабры (формалин 10%) и «кишечник, гепатопанкреас, карапакс» (заморозка).
  `raw_value` — исходный текст ячейки.
- **lab / sample_shipment**: из комментариев к шапкам 2026: ДНК → Россия, Тропцентр, Кантхо (секвенирование);
  мазки → Россия, Тропцентр. «Отправили на ген.анализ во Вьетнамскую компанию» (70 pc, 104 pc, 166 pc)
  → лаборатория «Вьетнамская компания (ген. анализ)». `sent_on` неизвестна → NULL.
- **catch_record**: заметки под таблицей особей и числа из комментариев к тралениям
  («10 plotosus», «2 плотосуса, 2 пангасиуса»). Купленное/взятое у рыбаков («купили у другого рыбака 2 плотосуса») —
  НЕ прилов траления, только в `notes`.
- **analysis**: пусто (результатов пока нет).

## Технические соглашения

- Python ≥ 3.11, стандартный `sqlite3` + `openpyxl`. Без ORM и pandas на первом этапе (пользователь учит SQL).
- Виртуальное окружение: `python -m venv .venv && source .venv/bin/activate && pip install -e '.[dev]'`
  (на Arch системный pip запрещён — только venv).
- Весь импорт — одна транзакция; при ошибке — откат и понятное сообщение (лист, ячейка, значение).
- Парсеры — чистые функции без доступа к БД, с docstring и примерами.
- SQL — параметризованные запросы (`?`), никакой подстановки строк.
- Код и идентификаторы — на английском, комментарии, docstring, сообщения CLI — на русском.
- `ruff` для стиля, `pytest` для тестов; тесты не должны зависеть от `output/`.
- `output/`, `.venv/`, `*.db` — в `.gitignore`. Предложить пользователю `git init` и первый коммит после этапа 1.
