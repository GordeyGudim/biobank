### Пояснения

- **STRICT** — режим таблицы SQLite (с версии 3.37; у нас 3.53): в колонку REAL нельзя записать
  текст, в INTEGER — дробное число. Без него SQLite молча сохранит «21,3 см» в колонку TL.
- **Почему ключ меток такой сложный.** Проверка данных показала: у ДНК, мазка и кишечника одной
  особи метка одинаковая («26 ph») — так записано в Excel, это норма (301 группа). Поэтому
  уникальность — в пределах особи, типа образца и органа. `ifnull(organ,'')` нужен, потому что в
  SQLite два пустых (NULL) органа считаются разными и дубль прошёл бы. Метку, уникальную на всю
  базу, ставить нельзя: «26 ph б» стоит у 26 особей Аквахозяйства (копипаст в Excel, записан в
  журнале проблем № 6).
- **Почему `IS`, а не `=` в проверках дат.** `date('25.09.25')` даёт NULL, а сравнение с NULL
  в SQLite не считается нарушением — с `=` неверная дата прошла бы. Проверено.
- **`created_by` = NULL** означает «перенесено из Excel». `created_by` (кто внёс) ≠
  `identified_by` (кто определил вид): лаборант может внести определение, сделанное профессором.
- **Журнал изменений пишет программа**, а не триггеры базы: только программа знает, какой
  пользователь вошёл на сайт. Команды CLI пишут `user_id = NULL`.
- **`record_key` — текст**, а не ссылка: запись могут удалить, а журнал должен остаться; у
  отправки ключ составной (`sample_id=812, lab_id=1`).
- **Пароли** хранятся только как хеш (scrypt): по хешу пароль не восстановить.

## Как перейти

Переносить данные вручную не нужно. До окончания этапа D рабочая база пересобирается из Excel,
поэтому после согласования: `db/schema.sql` заменяется на v3, импорт обновляется под новые
колонки (`source`, пустые `created_by`), база собирается заново. Миграции (перенос данных из
старой схемы в новую) понадобятся только для изменений после перехода на сайт — для этого
`user_version`.

## Что затронет в программе (оценка)

- импорт: заполнять `data_issue.source`; `identified_by` — пока пусто (имён в Excel нет);
- правки и ввод (`edit.py`, `entry.py`, `records.py`): записывать `created_by`/`created_at`
  и строки `change_log`; проверка прав по ролям;
- `checks.py`: `source = 'проверка'` вместо распознавания по тексту описания;
- сайт: вход, страница админа (пользователи и роли), «кто внёс» в карточках, справочник людей;
- сравнение баз перед импортом (`compare_databases`) — новые таблицы учтёт само (по схеме).

## Решения по вопросам (пользователь, 2026-10-19)

1. Записи из Excel (`created_by` = NULL) правит только куратор — да, так задумано.
2. Справочники (виды, лаборатории, сети, города, провинции) добавляет исследователь — поэтому
   `created_by`/`created_at` есть и у справочников; исследователь правит добавленное им, остальное —
   куратор. При вводе сайт предупреждает о похожих названиях (как о местах ближе 200 м).
3. Роль участника экспедиции — свободный текст.
4. Внутренние имена таблиц и колонок — английские (как во всей схеме и в коде); всё, что видят
   люди (сайт, карточки, выгрузки, отчёты), — по-русски.

## Дополнение 2026-10-20: session_version

**Зачем.** Сессия сайта — подписанная cookie с номером пользователя. Сервер не может отозвать
такую cookie: после «Выйти» или смены пароля скопированная раньше cookie продолжала бы
работать (проверено). Счётчик в учётной записи решает это: сайт кладёт в сессию
`(user_id, session_version)` и на каждом запросе сверяет версию с базой; выход, смена и
сброс пароля, закрытие входа увеличивают её на 1 — все прежние сессии недействительны
(«Выйти» выкидывает все устройства человека — так проще и надёжнее).

Без изменения схемы рассмотрены и отклонены: отпечаток хеша пароля в cookie (не отзывает
при выходе), `last_login_at` как версия (вход на втором устройстве выкидывал бы первое,
смысл колонки искажается), отзывы в `change_log` (журнал — история, не состояние).

```diff
-    last_login_at TEXT CHECK (last_login_at IS NULL OR datetime(last_login_at) IS last_login_at)
+    last_login_at TEXT CHECK (last_login_at IS NULL OR datetime(last_login_at) IS last_login_at),
+    session_version INTEGER NOT NULL DEFAULT 0 CHECK (session_version >= 0)  -- +1 при выходе, смене/сбросе пароля: старые сессии недействительны
```

`PRAGMA user_version` остаётся 3: на сайт ещё не перешли, рабочая база пересобирается из
Excel (миграция не нужна). Одобрено пользователем 2026-10-20; коллеге сообщено.
