# База данных уловов, Вьетнам 2025–2026

## Что в папке

| Файл | Что это |
|---|---|
| `vietnam_fish.db` | Готовая база SQLite со всеми данными из Excel |
| `schema.sql` | Описание таблиц (CREATE TABLE) с комментариями |
| `import_excel.py` | Скрипт, который собирает базу из Excel-файла |
| `export_xlsx.py` | Выгружает базу обратно в Excel для просмотра |
| `vietnam_fish_tables.xlsx` | Все таблицы базы в Excel, по листу на таблицу; первый лист — список проблем |

## Как открыть базу

1. Скачайте бесплатную программу **DB Browser for SQLite** (https://sqlitebrowser.org).
2. Нажмите «Открыть базу данных» и выберите `vietnam_fish.db`.
3. На вкладке «Данные» можно смотреть таблицы, на вкладке «SQL» — писать запросы.

## Что лежит в базе

| Таблица | Строк | Что это |
|---|---|---|
| `expedition` | 3 | Донг-хап, Виньлонг, Кантхо: даты, размер сети |
| `event` | 24 | Выезды, по одному на каждый лист Excel |
| `haul` | 95 | 94 траления и 1 точка лова рыбака (Виньлонг, Точка 6.) |
| `haul_point` | 189 | Замеры воды на старте и финише тралений |
| `taxon` | 8 | Справочник видов в одном написании |
| `specimen` | 462 | Особи (461 с номером и одна «ХХ» без номера) |
| `sample` | ~1220 | Образцы: ДНК, гистология по органам, мазки, кишечник, целые особи |
| `catch_record` | ~50 | Прилов и улов из заметок внизу листов и комментариев к тралениям |
| `data_issue` | ~50 | Спорные значения, найденные при импорте |

Готовые представления:
- `v_specimen`: особь со всем контекстом (вид, экспедиция, дата, образцы) одной строкой;
- `v_haul_water`: средние параметры воды по каждому тралению.

## Какие решения приняты при импорте

- Числа вида `10,103733.`, `105, 96480`, `29,3.` прочитаны как обычные числа.
- 155 pc: значение SL, которое Excel превратил в дату, восстановлено как 29,9.
- Время `10.48` и `11.08` (Виньлонг, Точка 1.) прочитано как 10:48 и 11:08.
- Названия видов приведены к одному написанию. Уверенность определения хранится отдельно: «точно», «предп.», «до рода» (для *sp.*) или «не определён».
- Колонка гистологии разбита на отдельные образцы по органам: «26 ph a – печень, 26 ph б – почки» стало двумя строками в `sample`.
- «Целая рыба», «заспиртовали целиком» и т. п. записаны как образец «целая особь», а у особи стоит `whole_fixed = 1`.
- У 1 pc и 2 pc (Донг-хап, Точка 2) значения гистологии и мазка, похоже, перепутаны местами. Импортированы как гистология (печень) и мазок, запись об этом есть в `data_issue`.
- Особи от рыбаков внутри «точек» (118 pc, 138–142 pc, 64–69 pc) и на листе «Рыбак 22.08» получили `origin = 'рыбак'` и свои координаты.
- Куда отправлены пробы в 2026 году (Россия, тропцентр, Кантхо) взято из комментариев к шапке и записано в `sample.storage`.
- **Траления у особей не заполнены** (`specimen.haul_id` пустой). В таблице этой связи нет, её нужно восстановить по полевому журналу. Исключение — особи 64–69 pc, они привязаны к точке лова рыбака.

## Примеры запросов

```sql
-- Сколько особей каждого вида в каждой экспедиции
SELECT экспедиция, вид, count(*) AS особей
FROM v_specimen GROUP BY экспедиция, вид ORDER BY экспедиция, особей DESC;

-- Все пробы печени Plotosus canius с метками пробирок
SELECT s.label AS особь, p.label AS пробирка, e.sheet_name AS лист
FROM sample p
JOIN specimen s USING (specimen_id)
JOIN taxon t USING (taxon_id)
JOIN event e USING (event_id)
WHERE t.name = 'Plotosus canius' AND p.organ = 'печень';

-- Средние параметры воды по экспедициям
SELECT экспедиция, round(avg(глубина_м),1) AS глубина, round(avg(t_воды),1) AS t_воды,
       round(avg(o2_pct),1) AS o2, round(avg(ph),2) AS ph
FROM v_haul_water WHERE kind = 'трал' GROUP BY экспедиция;

-- Особи, чьи ДНК-пробы отправлены в Россию
SELECT s.label, p.label AS пробирка, p.storage
FROM sample p JOIN specimen s USING (specimen_id)
WHERE p.sample_type = 'ДНК' AND p.storage LIKE '%Россия%';

-- Список того, что нужно проверить
SELECT category, sheet_name, cell, object, raw_value, description
FROM data_issue WHERE resolved = 0 ORDER BY category;
```

## Как дополнять и исправлять

Привязать особь к тралению, когда номер траления стал известен из журнала:

```sql
UPDATE specimen
SET haul_id = (SELECT h.haul_id FROM haul h JOIN event e USING (event_id)
               WHERE e.sheet_name = 'Точка 5' AND h.haul_no = 6 AND h.kind = 'трал')
WHERE label = '12 pc';
```

Исправить опечатку и отметить проблему как решённую:

```sql
UPDATE specimen SET sl_cm = 19.8 WHERE label = '149 pc';   -- значение из журнала
UPDATE data_issue SET resolved = 1 WHERE object = '149 pc';
```

Есть два способа вести данные дальше:
1. Исправлять прямо в базе (запросами или в DB Browser). После этого Excel больше не главный источник.
2. Исправлять в Excel и пересобирать базу командой
   `python3 import_excel.py source.xlsx vietnam_fish.db`
   (нужны Python 3 и пакет `openpyxl`: `pip install openpyxl`).

Выберите один способ, чтобы не было двух разных версий данных.

## Переход на PostgreSQL

`schema.sql` почти без изменений работает в PostgreSQL. Нужно заменить
`INTEGER PRIMARY KEY` на `INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY`, а `group_concat` на `string_agg`. Для работы с картой к PostgreSQL можно подключить расширение PostGIS и хранить координаты как точки.
